# 모바일 퀴즈 인터페이스 사진 기반 개선 프롬프트

## 기준 화면

- 기준 캡처: 367 × 662 px 세로 모바일 화면
- 대상: `콩쥐야_줘때써.html` 퀴즈 화면
- 목표: 현재 기능과 게임 규칙은 유지하면서, 사진에서 확인되는 시각적 위계·가독성·장면 비율 문제를 해결한다.

## 사진에서 확인된 문제

1. 상단 헤더 중앙이 비어 있다.
   - 왼쪽 닫기 버튼과 오른쪽 제어 버튼 사이의 넓은 공간이 아무 정보도 주지 않는다.
   - 현재 훈련 이름을 숨겨 두어 사용자가 어떤 퀴즈를 플레이 중인지 상단에서 확인할 수 없다.

2. HUD가 네 개의 작은 카드처럼 분절되어 보인다.
   - 점수·콤보·물·시간의 라벨이 지나치게 작다.
   - 카드별 테두리가 반복되어 상단에서 시각적 잡음이 생긴다.

3. 문제 카드의 장식성이 장면보다 강하다.
   - 금색 외곽선과 큰 패널이 장면 위에서 과하게 튄다.
   - 문제 진행 표시는 너무 작고, 문제 본문은 상대적으로 과도하게 크다.

4. 장면 안의 캐릭터 비율이 불균형하다.
   - 콩쥐는 너무 작고 장독대는 너무 크다.
   - 두꺼비가 장독대 구멍보다 커 보이며 장면의 중심을 과하게 차지한다.
   - 콩쥐와 장독대 사이의 물 붓기 동작 공간이 명확하지 않다.

5. 하단 상태 정보가 거의 읽히지 않는다.
   - `FEVER 준비`, 배수, 피버 게이지, 피드백 문구가 너무 작다.
   - 기능은 존재하지만 실제 모바일 화면에서 정보 전달력이 낮다.

6. 키패드의 `전체` 라벨이 직관적이지 않다.
   - 실제 기능은 입력값 전체 삭제인데 `전체`만 표시되어 의미를 바로 파악하기 어렵다.

7. 367 × 662처럼 짧은 모바일 화면에서도 장면·상태·입력창·키패드가 모두 한 화면에 들어가야 한다.
   - 스크롤을 만들지 않는다.
   - 장면을 200px 수준으로 과도하게 축소하지 않는다.
   - 키패드 터치 영역을 지나치게 작게 만들지 않는다.

## 구현 지시

### 상단 헤더

- 숨겨 둔 훈련 제목을 다시 표시한다.
- 카테고리 보조 문구는 모바일에서 숨긴다.
- 제목은 한 줄 ellipsis로 처리하고 10~12px 범위로 유지한다.
- 제어 버튼은 32px 정방형으로 정리한다.

### HUD

- 네 개의 독립 카드가 아니라 하나의 계기판 스트립처럼 보이게 한다.
- 바깥 테두리는 한 번만 사용하고 항목 사이에는 얇은 구분선만 둔다.
- 값은 약 14px, 라벨은 약 7.5px 이상으로 유지한다.

### 문제 카드

- 외곽선을 한 겹으로 줄이고 배경을 조금 더 투명하게 한다.
- 기준 높이는 약 62~64px로 줄인다.
- 짧은 문제는 18~22px, 중간 문제는 16~20px, 긴 문제는 13~17px 범위에서 자동 축소한다.
- 진행 정보는 9px 수준으로 올린다.

### 장면 비율

모바일 `#layeredScene`에서 다음 비율을 목표로 한다.

- 콩쥐: 화면 폭 약 32~33%, 높이 약 72%
- 바가지: 화면 폭 약 20%, 높이 약 28%
- 장독대: 화면 폭 약 37%, 높이 약 68%
- 두꺼비: 화면 폭 약 15%, 높이 약 20%

두꺼비는 모든 장독대 스킨에서 동일한 모바일 기본 크롭을 우선 적용하고, 기존 원본 PNG는 수정·재압축하지 않는다.

### FEVER / 피드백

- 피버 라벨과 배수는 최소 9px로 올린다.
- 피버 게이지는 최소 4px 높이를 유지한다.
- 피드백 문구는 9.5px 정도로 올리고 23px 이상의 상태 영역을 확보한다.

### 키패드

- 숫자 버튼은 최소 40px 높이를 유지한다.
- 입력 표시창은 32~34px 높이를 유지한다.
- `전체`는 기능 변경 없이 화면에 `지우기`라고 표시한다.
- 확인 버튼은 기존 동작과 색상 위계를 유지한다.

## 금지 사항

- 퀴즈 정답 판정 로직 변경 금지
- 점수·콤보·피버 계산 변경 금지
- 저장 데이터 형식 변경 금지
- PNG 재압축·리사이징·WebP 변환 금지
- 신규 캐릭터 이미지 생성 금지
- 모바일 화면에 세로 스크롤 추가 금지

## 검증 조건

1. 367 × 662 viewport에서 `document.scrollWidth <= innerWidth`, `document.scrollHeight <= innerHeight`를 만족한다.
2. 상단 훈련 제목이 visible이며 ellipsis 가능한 실제 폭을 가진다.
3. 장면 높이는 260px 이상 유지한다.
4. 콩쥐와 장독대 레이어의 모바일 폭 비율이 서로 유사한 범위에 들어간다.
5. 두꺼비 레이어는 장독대보다 명확히 작다.
6. 피버·피드백 글자가 기존보다 읽기 쉬운 크기로 계산된다.
7. 숫자 키패드 버튼 높이가 40px 이상이다.
8. `keypad-clear`의 화면 표시 문구는 `지우기`다.
9. 기존 레이어 장면 smoke test와 정답 제출 테스트가 모두 통과한다.
